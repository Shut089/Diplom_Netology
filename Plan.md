# План тестирования приложения "Мобильный хоспис"

## 1. Объект тестирования

Мобильное приложение "Мобильный хоспис".

Приложение предназначено для просмотра и управления новостями хосписа, а также просмотра тематических цитат.

Тестирование проводится на Android API 36.

## 2. Цель тестирования

Проверить основной функционал приложения и убедиться, что пользователь может:

- авторизоваться в приложении;
- просматривать новости;
- фильтровать и сортировать новости;
- создавать новости;
- редактировать новости;
- удалять новости;
- изменять статус новости;
- просматривать тематические цитаты;
- переходить между разделами приложения;
- выйти из учетной записи.

Также необходимо автоматизировать основные пользовательские сценарии с помощью UI-тестов.

## 3. Функционал приложения

### Авторизация

Будут проверены:

- вход с правильным логином и паролем;
- вход с неправильным логином;
- вход с неправильным паролем;
- вход с пустым логином;
- вход с пустым паролем;
- вход с пустыми полями;
- выход из учетной записи.

Данные для успешной авторизации:

- логин: `login2`;
- пароль: `password2`.

### Главный экран

Будут проверены:

- открытие главного экрана после авторизации;
- отображение блока новостей;
- раскрытие и закрытие новости;
- переход ко всем новостям;
- переход в раздел с тематическими цитатами;
- работа главного меню.

### Новости

Будут проверены:

- отображение списка новостей;
- раскрытие и закрытие новости;
- сортировка новостей;
- переход к фильтрации;
- переход в панель управления новостями.

### Фильтрация новостей

Будут проверены:

- фильтрация по категории;
- фильтрация по дате;
- фильтрация активных новостей;
- фильтрация неактивных новостей;
- совместное использование нескольких параметров;
- кнопка FILTER;
- кнопка CANCEL.

### Панель управления новостями

Будут проверены:

- отображение списка новостей;
- создание новости;
- редактирование новости;
- удаление новости;
- просмотр информации о новости;
- изменение статуса новости;
- сортировка;
- фильтрация.

### Создание новости

Будут проверены поля:

- Category;
- Title;
- Publication date;
- Time;
- Description;
- Active.

Также будут проверены:

- создание новости с корректными данными;
- обязательность заполнения полей;
- отмена создания новости;
- сохранение новости;
- работа переключателя Active.

### Редактирование новости

Будут проверены:

- изменение категории;
- изменение названия;
- изменение даты;
- изменение времени;
- изменение описания;
- изменение статуса;
- сохранение изменений;
- отмена редактирования.

### Удаление новости

Будут проверены:

- удаление существующей новости;
- подтверждение удаления;
- отмена удаления.

### Тематические цитаты

Будут проверены:

- переход в раздел `Love is all`;
- отображение списка цитат;
- раскрытие карточки цитаты;
- закрытие карточки цитаты;
- прокрутка списка.

### Навигация

Будут проверены:

- переход между Main и News;
- переход в раздел тематических цитат;
- возврат на предыдущий экран;
- открытие меню пользователя;
- выход из приложения.

## 4. Виды тестирования

Планируется провести:

- функциональное тестирование;
- позитивное тестирование;
- негативное тестирование;
- тестирование пользовательского интерфейса;
- тестирование навигации;
- UI-автоматизацию основных пользовательских сценариев.

## 5. Уровень тестирования

Будет проводиться системное тестирование мобильного приложения через пользовательский интерфейс.

## 6. Тестовое окружение

Для тестирования используется:

- macOS;
- Android Studio;
- эмулятор Pixel 8;
- Android 16;
- API 36;
- архитектура arm64-v8a.

## 7. Инструменты

Для выполнения проекта планируется использовать:

- Android Studio;
- Android Emulator;
- Git;
- GitHub;
- Espresso;
- UI Automator при необходимости;
- JUnit;
- Allure.

## 8. Автоматизация

Автоматизации подлежат основные пользовательские сценарии приложения.

В первую очередь планируется автоматизировать:

- успешную авторизацию;
- проверки неправильных данных авторизации;
- переход между основными разделами;
- просмотр новостей;
- фильтрацию новостей;
- создание новости;
- редактирование новости;
- удаление новости;
- просмотр тематических цитат;
- выход из учетной записи.

Некоторые проверки интерфейса могут быть выполнены только вручную, если их автоматизация будет нецелесообразна.

## 9. Результаты тестирования

По результатам работы будут подготовлены:

- чек-лист `Check`;
- тест-кейсы `Cases`;
- UI-автотесты;
- Allure-отчет;
- инструкция по запуску автотестов в `README.md`;
- файл `Result.md` со сравнением времени ручного и автоматизированного тестирования.

## 10. Критерии начала тестирования

Тестирование можно начинать, если:

- проект успешно собирается;
- приложение устанавливается на эмулятор;
- приложение запускается на Android API 36;
- доступна авторизация.

## 11. Критерии завершения тестирования

Тестирование считается завершенным, если:

- выполнены проверки по чек-листу;
- выполнены запланированные тест-кейсы;
- основные тест-кейсы автоматизированы;
- выполнен прогон UI-тестов;
- сформирован Allure-отчет;
- зафиксированы найденные ошибки и результаты тестирования.
