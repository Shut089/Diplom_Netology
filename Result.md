# Результаты тестирования

## Общая информация

В рамках дипломного проекта было проведено ручное и автоматизированное тестирование мобильного приложения «Мобильный хоспис».

Цель тестирования — проверить основные пользовательские сценарии приложения, выявить дефекты и автоматизировать часть повторяющихся проверок.

Тестирование выполнялось на эмуляторе:

- Pixel 8;
- Android API 36.

Для тестирования использовались:

- чек-лист `Check.xlsx`;
- тест-кейсы `Cases.xlsx`;
- автоматизированные UI-тесты;
- Allure для формирования результатов автоматизированного прогона.

## Сравнение ручного и автоматизированного тестирования

Ручное тестирование основных сценариев заняло около **25 минут**.

Автоматизированный прогон 11 UI-тестов занял около **1 минуты 32 секунд**.

Автоматизированное тестирование позволяет значительно сократить время повторной проверки основных функций приложения.

Автотесты удобно использовать при повторных проверках после изменений в приложении.

При этом ручное тестирование также остается необходимым, так как во время ручной проверки были обнаружены дефекты, которые не выявлялись текущим набором автотестов.

## Найденные дефекты

### 1. Невозможно ввести текст на русском языке при создании новости

При создании новой новости невозможно ввести текст на русском языке.

**Шаги воспроизведения:**

1. Авторизоваться в приложении.
2. Перейти в раздел `News`.
3. Открыть панель управления новостями.
4. Нажать кнопку создания новой новости.
5. Установить курсор в поле названия или описания.
6. Попытаться ввести текст на русском языке.

**Фактический результат:**

Русские символы не вводятся.

**Ожидаемый результат:**

Пользователь должен иметь возможность вводить текст на русском языке.

По дефекту создан Issue в GitHub.

### 2. Для созданных новостей отображается один и тот же автор

После создания новости в качестве автора отображается `Лебедев Д.А.`.

**Шаги воспроизведения:**

1. Авторизоваться в приложении.
2. Перейти в раздел `News`.
3. Создать новую новость.
4. Сохранить новость.
5. Проверить имя автора.

**Фактический результат:**

В качестве автора отображается `Лебедев Д.А.` независимо от созданной новости.

**Ожидаемый результат:**

В новости должен отображаться фактический автор либо значение, предусмотренное требованиями приложения.

По дефекту создан Issue в GitHub.

Всего по результатам ручного тестирования создано **2 Issues в GitHub**.

## Allure

Для формирования результатов автоматизированного тестирования используется Allure.

В тестах применяются:

- `@Epic`;
- `@Feature`;
- `@Story`;
- `@Description`;
- `@Severity`;
- `Allure.step()`.

Для запуска Android-тестов используется `AllureAndroidJUnitRunner`.

Для создания скриншота при падении теста используется `ScreenshotRule` в режиме `FAILURE`.

Работа `ScreenshotRule` была проверена отдельным временным тестом с контролируемым падением. После проверки временный тест был удален.

По результатам финального прогона сформирован архив:

```text
allure-results.zip
```

Архив содержит результаты всех **11 автоматизированных тестов**.

## Особенности автоматизации

При создании автотестов использованы:

- Kotlin;
- JUnit 4;
- Espresso;
- UI Automator;
- Page Object;
- Allure;
- Android Studio;
- Gradle.

Автотесты разделены по функциональности приложения.

Для работы с экранами используется Page Object.

Прямое взаимодействие с элементами интерфейса вынесено из тестовых классов.

Тестовые классы:

```text
AuthorizationTest
NewsTest
LoveIsAllTest
NavigationTest
```

Для хранения тестовых данных используется `TestData.kt`.

Для управления состоянием пользовательской сессии используется `SessionPage`.

В тестах не используется `Thread.sleep()`.

Для ожидания появления элементов используется UI Automator.

Тесты не зависят от порядка запуска и могут выполняться как отдельно, так и общим набором.
