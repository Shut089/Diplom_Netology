# Дипломный проект «Мобильный хоспис»

## Описание проекта

Дипломный проект выполнен в рамках курса «Инженер по тестированию».

Цель проекта — провести ручное тестирование мобильного приложения «Мобильный хоспис» и автоматизировать основные пользовательские сценарии.

Приложение содержит следующий функционал:

- авторизация пользователя;
- просмотр новостей;
- создание и управление новостями;
- фильтрация и сортировка новостей;
- просмотр тематических цитат;
- навигация между разделами приложения;
- выход из учетной записи.

---

## Тестовая документация

В корне репозитория находятся:

- `Plan.md` — план тестирования;
- `Check.xlsx` — чек-лист;
- `Cases.xlsx` — тест-кейсы;
- `README.md` — инструкция по запуску проекта, тестов и формированию отчета;
- `Result.md` — результаты тестирования;
- `allure-results.zip` — архив с результатами прогона автотестов.

---

## Автоматизированные проверки

Автоматизированы основные сценарии:

- авторизация;
- негативные проверки авторизации;
- создание новости;
- проверка обязательных полей новости;
- отмена создания новости;
- переход в раздел `Love is all`;
- раскрытие карточки цитаты;
- навигация между `Main` и `News`;
- выход из учетной записи.

Всего реализовано 11 UI-тестов.

## Запуск проекта

### 1. Клонирование репозитория

В терминале выполнить:

```bash
git clone https://github.com/Shut089/Diplom_Netology.git
```

Перейти в папку проекта:

```bash
cd Diplom_Netology
```

---

### 2. Открытие проекта

Открыть Android Studio.

Выбрать:

```text
Open
```

и указать папку:

```text
Diplom_Netology
```

Дождаться окончания `Gradle Sync`.

---

### 3. Запуск эмулятора

В Android Studio открыть:

```text
Tools → Device Manager
```

Запустить эмулятор с Android API 36.

В проекте использовался:

```text
Pixel 8 API 36
```

Проверить подключение эмулятора можно командой:

```bash
adb devices
```

Устройство должно появиться в списке.

---

### 4. Запуск приложения

В верхней панели Android Studio выбрать конфигурацию:

```text
app
```

Выбрать запущенный эмулятор и нажать:

```text
Run
```

После сборки приложение запустится на эмуляторе.

При первом запуске откроется экран авторизации.

Для входа использовать:

```text
Login: login2
Password: password2
```

## Формирование Allure-отчета

### 1. Установка Allure

Проверить, установлен ли Allure:

```bash
allure --version
```

Если Allure не установлен на macOS, установить его через Homebrew:

```bash
brew install allure
```

После установки повторно проверить:

```bash
allure --version
```

---

### 2. Очистка старых результатов

Перед новым полным прогоном удалить результаты предыдущих тестов с эмулятора:

```bash
adb shell run-as ru.edu.qamid rm -rf files/allure-results
```

Также удалить старую локальную папку с результатами:

```bash
rm -rf allure-results
```

---

### 3. Запуск тестов

После очистки результатов запустить все тесты через Android Studio:

```text
Run 'Tests in ru.edu.qamid.tests'
```

Дождаться завершения полного прогона.

---

### 4. Выгрузка результатов Allure с эмулятора

После выполнения тестов результаты находятся внутри приложения на эмуляторе.

Проверить наличие результатов:

```bash
adb shell run-as ru.edu.qamid ls -R files/allure-results
```

Для выгрузки результатов в корень проекта выполнить:

```bash
adb exec-out run-as ru.edu.qamid tar -C files -cf - allure-results | tar -xf -
```

После выполнения команды в корне проекта появится папка:

```text
allure-results
```

Проверить содержимое:

```bash
ls allure-results
```

В папке должны находиться файлы результатов тестов с расширением:

```text
-result.json
```

---

### 5. Генерация Allure-отчета

Для генерации HTML-отчета выполнить:

```bash
allure generate allure-results --clean -o allure-report
```

После выполнения команды появится папка:

```text
allure-report
```

---

### 6. Открытие Allure-отчета

Для просмотра отчета выполнить:

```bash
allure open allure-report
```

Allure запустит локальный сервер и откроет сформированный отчет в браузере.

В отчете можно увидеть:

- количество выполненных тестов;
- успешные и упавшие тесты;
- Epic;
- Feature;
- Story;
- Description;
- Severity;
- шаги выполнения тестов;
- продолжительность выполнения.

При падении теста `ScreenshotRule` добавляет скриншот в результаты Allure.

## Используемые технологии

При автоматизации использовались:

- Kotlin;
- JUnit 4;
- Espresso;
- UI Automator;
- Page Object;
- Allure;
- Android Studio;
- Gradle.

Для работы с экранами приложения используется Page Object.

Прямое взаимодействие с элементами интерфейса вынесено из тестовых классов.

В тестах не используется:

```text
Thread.sleep()
```

Для ожидания появления элементов используется UI Automator.

Тесты не зависят от порядка запуска и могут выполняться как отдельно, так и общим набором.
